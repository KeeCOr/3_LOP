# LOP 기획서

현재 문서 기준 버전: 0.4.22

!LOP gameplay preview

문제 정의

전략 보드게임과 짧은 로그라이크 선택지를 좋아하는 플레이어가 10~20분 세션에서 빠르게 판단하고 싶을 때, 선택 결과와 다음 목표가 즉시 읽히지 않으면 보드 이동이 단순 주사위 굴림처럼 느껴져 이탈한다.

LOP는 Monopoly식 이동 감각과 Risk식 병력 판단을 짧은 PC 보드게임 루프로 압축해, 한 번의 선택이 캐릭터 성장, 병력 구성, 다음 장면의 유불리로 이어지는 게임이다.

주 페르소나

  • 이름/나이/직업: 윤하겸, 25세, 전략 보드게임 팬
  • 사용 맥락: 퇴근 후 20분 안에 끝나는 전략 세션을 원한다. 규칙 설명이 긴 게임보다 선택 결과가 바로 보이는 게임을 선호한다.
  • 선호: 이동, 이벤트, 전투, 보상 선택이 다음 턴의 판단으로 이어지는 구조.
  • 이탈 포인트: 선택 후 무엇이 좋아졌는지, 다음 목표가 무엇인지 보이지 않을 때.

핵심 루프

플레이어가 현재 보드와 목표를 확인한다 -> 주사위/이동 결과로 칸 이벤트를 만난다 -> 전투, 징집, 건설, 보상 선택을 처리한다 -> 골드, 병력, 영토 상태가 바뀐다 -> 다음 이동에서 더 나은 선택을 시도한다.

MVP 가설

가설확인 방법
선택 결과와 다음 목표가 같은 화면에 나오면 첫 세션 이탈이 줄어든다.첫 3분 안에 다음 행동 CTA를 이해하는지 관찰한다.
병종 상성 설명이 전투 결과에 붙으면 패배 납득도가 오른다.전투 후 재시도율과 결과 불만 피드백을 비교한다.
캐릭터 고유 능력이 이동/전투/영토 중 하나에 명확히 연결되면 재플레이 의도가 오른다.2회차에서 다른 캐릭터 선택 비율을 측정한다.

현재 구현 상태

  • Next.js 기반 웹 앱과 Electron 래퍼 구조가 존재한다.
  • 시작 흐름은 목표 확인 -> 세팅 -> 캐릭터 공개 -> 보드 루프로 이어진다.
  • chance-card 결과는 즉시 결과와 다음 판단 이유를 설명하도록 보강됐다.
  • 데스크톱 빌드 경로는 C:/Development/3_LOP/lop의 npm run build 후 C:/Development/3_LOP/electron의 npm run dist 순서다.
  • 현재 프로젝트 판단은 보류 상태이며, 보류 해제에는 캐릭터 밸런스와 결과 설명의 추가 검증이 필요하다.

게임 구성

구성현재 방향
이동주사위와 캐릭터 보너스로 이동 결과를 만든다.
이벤트전투, 징집, 건설, 보상, 강제 판매 등 짧은 모달 이벤트 중심.
전투병력 수와 병종 상성으로 결과를 계산하고 결과 이유를 설명한다.
성장캐릭터 능력과 영토 상태가 다음 턴의 선택 근거가 된다.
목표상대 거점을 압박하고 골드/병력/영토 우위를 만든다.

UX 규칙

  • 선택지는 한 화면에 5개 이하로 유지한다.
  • 선택 직후 400ms 이내에 결과 요약, 변화한 수치, 다음 추천 행동을 보여준다.
  • 전투 결과에는 승패뿐 아니라 병종 상성, 병력 차이, 주요 손실 이유를 표시한다.
  • 모바일/좁은 화면에서는 보드보다 현재 선택 모달과 다음 CTA를 우선 표시한다.

cd C:/Development/3_LOP/lop && npm run build
cd C:/Development/3_LOP/electron && npm run dist

출력 경로: C:/Development/3_LOP/release/LOP_v0.4.22_portable.exe

남은 리스크와 다음 우선순위

  1. 캐릭터 밸런스 미기입 항목을 확정해야 보류 판단을 다시 볼 수 있다.
  2. 전투 결과 설명이 실제 플레이에서 충분히 납득되는지 확인해야 한다.
  3. 대량 dirty 빌드 산출물과 release 삭제 상태를 정리해야 배포 신뢰도가 회복된다.
  4. Electron package.json의 일부 메타데이터는 다음 config pass에서 ASCII/UTF-8 안전 문자열로 정리하는 것이 좋다.
